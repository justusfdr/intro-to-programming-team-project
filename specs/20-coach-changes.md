# Spec 20: The coach moves and deletes events, and undo
Asked for by the owner on 13 Nov 2026: "It would be good if the coach could also move events. I say: 'I want to move something.' Or delete. And things I can undo." Plan: `docs/ontology.md` (`draft_plan` and its statuses, `accept_draft`, `undo_draft`, R1, R4, R10, R11, R21 to R23, R26, R28, R38, A21; changes of 13 Nov 2026 on this branch). Branch: `20-coach-changes`, built on `19-coach` (spec 19).

## Why
Spec 19's coach only adds events. Evenings often go the other way: "move the lecture to the afternoon", "drop the gym tomorrow", and after a look at the result, "put it back". The coach should propose these too, under the same rule as before: Claude only proposes, our server checks, nothing changes before the user accepts, and an accepted draft can be taken back as a whole.

## What
- [x] A draft holds new events (as before), moves of existing events (new start and end; title, goal and everything else stay) and deletes of existing events: 1 to 30 in all. Nothing changes before "Add to calendar" / "Apply changes".
- [x] How the assistant names an event (R22): with every message each event in the data block gets a reference valid for that one request ("e1", "e2", …) and a flag whether the coach may change it; no event id goes to Claude. The server turns a reference in the answer back into the event at once and keeps the event's id and `updated_at` in the draft; an unknown reference fails the checks.
- [x] Which events the coach may change: the user's own, timed, not from Outlook (R11), not part of a series (R28), not started yet; each at most once per draft. Anything else fails the checks; the prompt tells the coach to say so in words.
- [x] Checks (R23, extended; `src/lib/chat/checks.ts`, pure): a move's times obey `edit_event` (start before end, at most 24 hours) and start between now and the end of the 14th day; overlaps are checked on the calendar as it would be after the whole draft (new and moved events must not overlap each other or a remaining timed event with `may_overlap` = false; an event that may overlap never blocks; a moved or deleted event no longer blocks at its old time). One failed check rejects the whole answer.
- [x] `accept_draft` applies everything in one transaction: the checks again against the calendar as it is now, every changed event still with the `updated_at` the draft remembers (R4), else "This draft is out of date. Ask again". Moves and deletes are the same statements as `edit_event` and `delete_event`, so Outlook follows as after a change by hand (R26); the screen asks for an Outlook send right after, as the calendar does. The draft remembers what undo needs.
- [x] `undo_draft` (new, `POST /api/chat/drafts/[id]/undo`): only while the draft is `accepted` and every event it created or moved is unchanged since accepting. Deletes the created events, moves the moved ones back, creates the deleted ones again with their fields (a new id; a done event done again, R38), in one transaction; the draft becomes `undone` (final). "Undone. Your calendar is as before." / "This can no longer be undone".
- [x] Database (`supabase/migrations/20261124000000_coach_changes.sql`): a draft's `changes` (the user's role may add them with the draft, never change them) and `undo` (written only by the database's apply and undo functions, from the rows themselves, so it cannot be forged); drafts of changes only and the status `undone` are the only loosened limits; the old accept function refuses a draft with changes, so the code of `19-coach` cannot accept one while dropping its changes. Works with the code on `main` and `19-coach`.
- [x] What Claude is told (`prompt.ts`): move or delete only when the person asks, by reference only, never events flagged as not changeable (say so instead), plan new events around what stays; the answer format has a list of changes; earlier drafts carry their changes in words (title, old time, new time) so "put it back" can be understood.
- [x] The screen (`DraftCard.tsx`, `day-sketch.ts`): a moved event at its new time like a proposal with "Moved from 14:00", its old place as a pale dashed outline; a deleted event pale, struck through, "Removed"; the screen-reader list says the same. "Add to calendar" for a draft that only adds, "Apply changes" otherwise. After accepting, "Undo" next to "Open calendar"; after undo the pill says "Undone" and the buttons are gone. A day section for every day the draft touches, also the old day of a moved event.

## Out of scope
Changing an event's title, goal, location or `may_overlap` through the coach; changing events of a series or Outlook events through the coach (the coach says so; the calendar does it); a time limit on undo; undoing a draft accepted by the code of spec 19 (it has no undo data: "This can no longer be undone"); streaming answers.
