# Spec 16: The event editor's frame, as in the prototype
**This branch (`prototype-style`) is a variant for the team to compare with `main`.** It turns the app, step by step, into a copy of our first prototype's screens, with only the changes the owner decided. This is step 5. Plan: `docs/ontology.md` (R39 and the location limit of `create_event` and `edit_event`, added on this branch 12 Nov 2026; R1, R4, R10, R11, R26, R28, R29). One additive migration: `supabase/migrations/20261122000000_event_location.sql`.

## Why
The owner sent the prototype's event panel as "how it should look": a card that floats next to the block and saves every change at once. The rebuild had a panel at the right edge with a Save button, a native date field, no location field for app events, and the sections in another order. Only the frame is built now; the sections that stand on their own come later from the teammates, each as one more component.

## What
- [ ] The editor of an event is the prototype's 360 px card next to the block it belongs to (right of it, else left of it, always inside the window, as tall as fits); on phones a sheet from below. Esc and a click outside close it and the focus goes back; Tab stays inside.
- [ ] An existing event has no Save button: every change is `edit_event` at once with the `updated_at` the screen last saw (R4, R39); changes are sent one after another, each with the `updated_at` of the answer before. The block in the calendar moves at once; a refusal puts the field back and shows the ontology's message (and "Reload" when another device saved first). The title and the location are saved when the field is left or after a short pause, not on every key; Esc in the title puts back the title it had; an empty title is never sent.
- [ ] An event of a series asks "This event / This and following events" in the footer before a change is saved and before a delete (R28), as before; Cancel puts the field back.
- [ ] Sections in the prototype's order and look, each its own component in `src/components/calendar/editor/`: header (goal tile, title, close); chips (Done, Repeating, From Outlook, Not sent to Outlook, Overlaps another event); WHEN (the date button with its folded month calendar, start, end with the length; the all-day switch next to the heading, first and last day for an all-day event, and for a new event the repeat choice); GOAL chips; LOCATION (a field with the pin icon); then ours: OVERLAP. Footer: black "Start focus", "Mark done" / "Reopen", the bin (one event goes at once with Undo in the toast).
- [ ] An Outlook event shows its title, time and location as text and changes only its goal and done status (R11); its location cannot be set or cleared (refused by the server and the database).
- [ ] Location: `create_event` and `edit_event` take it, up to 200 characters, empty means none, left out of an edit it stays ("Location can be at most 200 characters"); a series gets it on every event. An app event's location goes to Outlook with the event (R26). Database: a new event may be written with a location (insert right); a location is changed only through `app.set_event_location`, which works on the signed-in user's own app events and refuses Outlook events. Tall blocks show the location line, as in the prototype.
- [ ] A new event: the small card's "Add" creates it; "Add details" opens this editor with what was filled in (for repeat, all day, location, overlap); "Add event" creates it and the editor then edits the saved event.

## Out of scope
Work for later, each one more section component in the editor's list: to-dos inside an event, notes, the "How did it go?" rating with energy, the linked task, the travel line ("Leave by …", R27), guests. Also not here: the meeting link, editing an event past midnight as two days, undo of a field change.
