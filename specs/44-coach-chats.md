# Spec 44: The coach keeps chats by day, English only, no daily limit
Asked for by the owner on 17 Nov 2026; the team confirms with the merge. Plan: `docs/ontology.md` (`chat` and `chat_message` in sections 1 to 3, `draft_plan` in section 4, `send_message`, `delete_chat`, `clear_chat`, R1, R21, R22, R24, section 7, A6, the new A28; changes of 17 Nov 2026 on this branch). Branch: `44-coach-chats`, built on `main`.

## Why
The coach was one endless conversation: every message sent the last ten messages of everything ever said, and the only way to start fresh was to delete it all. People want a new chat for a new topic and to find yesterday's chat again, as in other chat apps. Three more things came up while using it: the German half was not needed, 20 messages a day was too few, and a dictated message came back into the field after it was sent.

## What
- [x] Chats (`supabase/migrations/20261215000000_coach_chats.sql`, `src/lib/server/chat/rows.ts`): a new table `app.chats` (title 1 to 80 characters, `created_at`, `updated_at` = the latest message). Every message belongs to one chat (`chat_messages.chat_id`, a two-column link so it is always the same user's chat; deleting a chat deletes its messages and with them their drafts; events stay). Row-level security: a user reads, starts and deletes only their own chats; the title is written once, by our server; `updated_at` moves only through the database.
- [x] Old messages: the migration makes one chat per user and day (in the user's time zone), titled with that day's first message of the user. The main branch's builds keep working against the same database: a message saved without a chat goes into the user's latest chat (or a new one), through a trigger, and a chat whose last message is deleted (the main branch's "Clear chat") goes too, so the list never shows an empty chat.
- [x] `send_message` (`src/lib/server/actions/send-message.ts`): takes `chatId` (a chat, `"new"`, or left out = the latest chat, as before). Claude receives only that chat's last 10 messages (R22), so a new chat starts without the others. A new chat is made together with the first turn, titled with the message (one line, cut to 80 characters), so a failed send leaves no empty chat (R1). A chat that is not the user's, unknown or deleted while Claude was asked: "This chat no longer exists", nothing saved. One open draft per user stays: a draft in one chat replaces the open draft of another.
- [x] `delete_chat` (`src/lib/server/actions/delete-chat.ts`, `POST /api/chat/chats/<id>/delete`), always allowed: the chat with its messages and drafts; events stay. It takes the same per-user lock as saving a turn, so a delete and an answer arriving at the same moment take turns. `clear_chat` now also deletes the chats.
- [x] The page (`src/app/coach/page.tsx`, `loadChatPage`): `/coach` shows the latest chat, `/coach?chat=new` an empty new chat, `/coach?chat=<id>` that chat (an empty new chat when it is not the user's). `/coach?plan=<goal>` (spec 43) starts a new chat.
- [x] The list (`src/components/coach/ChatList.tsx`, `src/lib/chat/chats.ts`): left of the conversation, the chats grouped by the day of their latest message ("Today", "Yesterday", "Mon, Nov 16"), newest first, the open chat marked, "New chat" at the bottom. On phones it opens from a button in the header, and a pen icon there starts a new chat. The header shows the chat's title and "Delete chat" (with a question first) instead of "Clear chat".
- [x] Search (asked for by the owner on 17 Nov 2026, `GET /api/chat/search?q=`, `src/lib/server/actions/search-chats.ts`, `src/lib/chat/search.ts`): a field above the list finds the user's own chats whose title or one of whose messages contains every word typed (ignoring case; % and _ are searched as typed; at most 8 words and 100 characters, longer is refused). The results replace the days while something is typed: newest first, at most 30, each with its day and an excerpt around the first hit, the words marked. A click opens the chat at that message (`&message=<id>`), which glows for a moment (with reduced motion it stays marked). Nothing is changed and nothing leaves our server; row-level security keeps it to the user's own chats (R3).
- [x] The page never scrolls as a whole: only the list and the conversation do (texts for screen readers inside the conversation used to stick out below it and made the page scroll).
- [x] No daily limit (R21): nothing is counted and nothing refused; the counter "17 of 20 messages left today" is gone. The counting function and columns stay in the database for the main branch's builds until this is merged.
- [x] English only (R24): no EN/DE switch; the browser listens for English; the coach always answers in English (the prompt says so); the German starter is replaced by an English one.
- [x] Voice (R24): the microphone sits on the right, next to the send button. While listening a wave of dots next to it rises with the voice (`VoiceWave.tsx`, the Web Audio API in the browser; nothing is recorded or sent); where the loudness cannot be read (no permission, iPhone and iPad) the dots breathe instead; reduced motion keeps them still.
- [x] Voice fix: sending (Enter or the button) while the microphone is on used to bring the dictated text back into the field, because the browser delivers its last results after it was told to stop. Sending and typing now end listening and drop whatever still arrives (`useSpeech.discard`); a second click on the microphone still takes the last words.

## Decisions
- A chat's day in the list is the day of its latest message, so a chat continued today shows under "Today".
- `/coach` opens the latest chat, not a new one, so an open draft is where the person left it; "New chat" is one click away.
- Sending without `chatId` goes into the latest chat, so a browser tab still open on the old page keeps working after the update.
- Tests that pinned the 20-message limit, the counting on a failed send and the German starter now pin the new behaviour (no limit, nothing counted, English only). The reviewer should read those changes: `send-message.test.ts`, `coach-todos.test.ts`, `coach-existing-todos.test.ts`, `coach-goal-routine.test.ts`, `chat-load.test.ts`, `CoachView.test.tsx`, `CoachPlan.test.tsx` (the new fields only), `voice.test.ts`, `prompt.test.ts`. The test harness can now stop before a migration (`createTestDb({ stopBefore })`, `migrateRest()`), to test what a migration does to rows saved before it.
- No daily limit means the costs of the AI service are no longer capped by the app; the provider account's spending limit (R21) is what caps them.

## Out of scope
Renaming chats, pinning chats, searching by meaning (only the words as typed), more than the latest 200 chats in the list, a daily limit per plan.
